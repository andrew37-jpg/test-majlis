# Данные и эксплуатационные границы

Приложение хранит Telegram ID/имя, данные заказа, его текущего владельца, историю с поколением владельца, очередь и технический аудит. Новые audit-снимки не копируют имена, товар, комментарии или платёжные URL. Старый audit остаётся сохранённым: его очистка без согласованного основания не выполняется.

`GET /api/me/export` требует Telegram initData и выдаёт только текущие собственные заказы (до 1000) и последние 100 событий своего текущего поколения. Это явно обозначенная ограниченная выгрузка; запрос полной выгрузки/удаления — через оператора. Кнопка находится в разделе «Помощь». Файл содержит персональные данные: пользователь выбирает, где его хранить.

`python manage.py privacy-plan --customer TELEGRAM_ID` — только локальная оценка количества записей; ничего не удаляет. Она не заменяет политику обработки данных.

Сроки хранения, основания обработки, реквизиты оператора, правила возвратов и обязательного сохранения документов, удаление старых журналов и backup требуют решения заказчика. Автоматическое удаление/анонимизация не включены: до согласования операции могут уничтожить нужные данные. Юридическое соответствие не подтверждено.

История переданного заказа хранится у магазина. Покупатель получает только события текущего поколения владельца. При миграции 002 история существующих заказов с доказанной передачей консервативно маркируется поколением 0 и не показывается покупателю; неясную принадлежность мы не угадываем. Доступ менеджера сохраняется.

Нет browser localStorage/sessionStorage/service worker с заказами. Ответы и fetch используют no-store. Перед открытием карточки сервер заново проверяет права. Уже полученные на устройстве сведения нельзя гарантированно отозвать удалённо; не оставляйте кабинет открытым на чужом устройстве.

Временный HTTP-туннель localhost.run заканчивает TLS у провайдера: он технически обрабатывает initData и ответы кабинета. Это согласованный режим тестирования, а не постоянный production-хостинг. Production требует `ENVIRONMENT=production`, `HTTPS_MODE=external`, постоянный HTTPS-домен и самостоятельно выбранную инфраструктуру. Управление ОС, резервным хранилищем и правовыми условиями остаётся у оператора.

## Обращения 0.7

customer_messages хранит Telegram ID, источник, текст (до 4096 символов), тип, время приёма и идентификаторы для дедупликации. Бот сохраняет только личные сообщения, поступившие ему; команды не превращаются в обращения. Из Mini App отправитель устанавливается сервером. Автоматического уведомления менеджеру/ответа клиенту не добавлено. Файлы и сторонние переписки не загружаются.

Входящие обращения доступны только сотрудникам с отдельным can_read_inbox, они не раскрываются любому менеджеру заказов. Собственная выгрузка включает до 1000 своих обращений. Сроки хранения, удаление/анонимизация сообщений и копий требуют согласованной операторской политики; автоудаления нет. Не сохраняйте секреты в обращениях, предупреждение есть перед отправкой. Смена/отзыв прав и 403 очищают клиентские рабочие данные; это не обещание удалить уже прочитанную сотрудником информацию.
