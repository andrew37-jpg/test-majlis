# Источники данных и подключения — 0.7

## Что подтверждено текущим кодом

Целевая БД приложения — PostgreSQL из DATABASE_URL. Mini App обращается только к API, не к БД. Старый источник заказчика и сайт не предоставлены. Адаптер сайта по выдуманным endpoint/полям не создавался.

| Данные | Текущий источник истины | Допустимое изменение / конфликт |
|---|---|---|
| Telegram ID/профиль | Проверенные initData; связь заказа задаёт уполномоченный менеджер | Передача покупателя требует явного подтверждения, поколения истории и сброса старой ссылки |
| Номер заказа, товар/комплектация, копейки | PostgreSQL, ручная работа менеджера | Версия + row lock, 409 при конфликте; изменения сайта не применяются без договора обмена |
| Этап доставки | PostgreSQL; ручной менеджер или подписанный событийный endpoint | У автоматики только существующая монотонная последовательность; у менеджера ручная коррекция |
| Трек и перевозчик | Отдельные ручные подтверждённые поля | Версия + row lock; новых adapters/URL трекинга нет |
| Ожидаемая дата | Ручная дата менеджера, отдельный флаг подтверждения | Дата без подтверждения — ориентир; внешняя ETA пока не импортируется |
| Оплата | Ручная разрешённая HTTPS-ссылка | Не равна paid; при смене суммы/товара URL убирается из кабинета; provider invoice не отменяется |
| Отдельное состояние заказа / оплаты | Не подключено | В ответе not_provided / not_confirmed, не вымышленные состояния |

Сейчас одна запись orders — один заказ с текстовым товаром/комплектацией. shipment — партия карго, не трек-номер. Подписанные события обновляют все связанные с партией заказы. Отдельные SKU/количества/товарные позиции/отправления не моделируются без правил источника.

## Отслеживание и свежесть

Сохраняются tracking_number/carrier/tracking_updated_at для ручного отслеживания. external_updated_at — время приёма допустимого внешнего события текущего или более позднего этапа; это не время физического перемещения у перевозчика. Запоздавший sequence и повтор event_id не освежают данные. Неверное событие откатывает транзакцию. Заказ delivered не откатывается старым автоматическим этапом. Отмены/возвраты отсутствуют в исходном словаре; новые запреты/состояния не выдуманы, необходимы правила заказчика.

После 24 часов без нового принятого события UI предупреждает о давности сведений. Это технический индикатор возраста, не SLA, не доказательство сбоя интеграции или задержки доставки. При отсутствии событий явно указано, что автоматические обновления не поступали. Последнее обновление заказа, ручного трека и внешнего события различаются.

Действующий /api/integrations/events — ВХОДНОЙ целевой контракт приложения, не документированный API сайта. Он принимает event_id, shipment, status, sequence и HMAC(timestamp.raw_body); production требует sequence. Повторы не дублируют историю/очередь. Неполученные события источник может повторить с тем же ID/нагрузкой; другие данные под тем же ID — 409. Протокол 0.6 не изменялся, контрольные суммы прежних payload совместимы. Он обновляет статусы существующих партий, **не синхронизирует создание заказов с сайта**.

Поллинг Mini App каждые 30 секунд обновляет локальные сведения; это не polling перевозчика. Внешний polling/webhook, сетевые таймауты и повторы для website adapter должны опираться на настоящий API. Сейчас исходящих запросов к неизвестному сайту нет.

## Что предоставить для сайта

1. URL сайта, документацию/версию API или исходники backend, sandbox; способ авторизации передать локально, без ключей в чате.
2. Модель клиента и подтверждённое сопоставление Telegram ID; стабильные order/customer/product/shipment/invoice IDs, валюты и единицы суммы.
3. Какие сущности authoritative на сайте, какие в MAJLIS; кто создаёт заказ, разрешённые обратные изменения, версии/updated_at и правила конфликтов.
4. Webhook/подписи/event IDs/порядок/retention replay либо polling/cursor/rate limits/timeout. Формат ошибок и допустимость повторов/idempotency key.
5. Связь партии с заказами и товарами; известные даты/местоположения/перевозчик; сценарии отмен/возвратов.
6. Правила счетов/ссылок/paid/refund/expiry и отмены у платёжного провайдера.

До получения материалов не подтверждены реальные адаптеры, внешняя синхронизация заказов и оплата. Нормализованный test import из LEGACY-MIGRATION.md остаётся отдельной подготовкой, не переносом настоящей старой базы.
