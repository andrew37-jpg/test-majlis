# Обновление установленного нового проекта до 0.7

0.7 продолжает фактическую версию PyCharm 0.6 с исправленным QR-парсером localhost.run. Старые 001–004 неизменны. Новые 005 добавляют назначения/отслеживание, 006 — узкие проверки ACL с блокировкой, 007 — отдельные полные разрешения и обращения. Ничьи реальные права менеджера автоматически не назначаются.

Сначала остановить main.py в PyCharm, сохранить приватную копию кода/.env и pg_dump, проверить restore отдельно; не удалять volume. Обновить текущие файлы, сохраняя .env/data/.venv. Runtime lock прежний. Выполнить python -m majlis.cli migrate и запустить конфигурацию MAJLIS из PyCharm. Открыть свежий кабинет через меню тестового бота. Старые окна могут содержать старый JS и HTTPS-адрес.

Интерфейс по умолчанию открывает покупателя. Менеджер открывает отдельный адрес /manager/ или скрытую команду /manager со своего Telegram ID. Кнопка менеджера у покупателя отсутствует, прямой запрос manager получает 403. Если менеджер также покупатель, собственные покупки доступны отдельно.

API совместим: прежние endpoint/поля сохранены; без X-MAJLIS-Cabinet сохраняется прежнее автоматическое определение контекста для старых клиентов. Новый frontend всегда передаёт контекст. Добавлены permissions/tracking в заказ, available_cabinets/can_create/manager_all в user, отдельный POST /api/orders/tracking. Эти поля не принимаются от клиента как подтверждение прав.

manage.py учитывает три новые таблицы при backup/restore. Восстановление старого 0.6 dump проверяйте исходниками 0.6, затем применяйте новые миграции на копии. Rollback не выполняет DROP таблиц и не подменяет рабочую базу автоматически. Отдельно учитывайте модель доступа старого API при откате.

Приёмка: покупатель/назначенный менеджер/только просмотр/обе роли/отзыв/прямые запросы, трек и история, неизменность платёжных ссылок, свежесть и потеря связи. Истинный сайт/провайдер и устройства проверяются отдельно.
