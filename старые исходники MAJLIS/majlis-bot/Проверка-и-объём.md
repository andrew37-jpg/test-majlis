Проверено в браузере: кабинет покупателя, пустое состояние, создание демонстрационного заказа через менеджера, изменение этапа и сохранение после перезагрузки. Интерфейс проверен на ширине 390 px, горизонтального переполнения в просмотренных клиентском и менеджерском экранах нет.

Автоматические проверки запускаются из tests/. Все результаты относятся к тестовым данным. Отдельная live-конфигурация проверялась локальным HTTP-сервером с подписанными фикстурами, без обращения к реальному Telegram-боту.

Демонстрационные суммы и даты придуманы только как тестовые данные, не являются сведениями о заказах магазина. Проверочный заказ MJ-DEMO-1044 создан через UI и сохранён в локальной demo-базе.

Результат: 23 из 23 автоматических проверок прошли. Счётчик получен из вывода unittest. В браузере также проверено изменение подтверждённой даты поставки и отображение её покупателю.


## Упаковка для PyCharm — версия 0.2

- main.py запускает HTTP-сервер, временный HTTPS и Telegram worker одной командой.
- telegram.env — локальный файл ключа и настроек; в архив не включается.
- /id и /manager добавлены; настройка кнопки web_app и меню проверены с имитацией Telegram API.
- Добавлены блокировка повторного запуска, проверка принадлежности HTTPS-адреса текущему серверу и завершение дочерних процессов.
- Используется truststore 0.10.5: системное хранилище сертификатов, TLS-проверка включена.
- **39 автоматических проверок прошли** (счётчик unittest). Полный suite запущен в отдельном окружении с зависимостью из requirements.txt.
- Реальный локальный launcher проверен из /private/tmp: сервер запустился, после SIGTERM launcher завершился с кодом 0, HTTP-сервер перестал отвечать.
- Реальное HTTPS-обращение к https://api.telegram.org вернуло HTTP 200 с системной проверкой сертификатов. Это проверка соединения, не проверка ключа, отправки сообщений или входа в Mini App.
- В текущей среде Quick Tunnel создал временный адрес, но его маршрут не заработал: DNS не разрешил имя, cloudflared сообщил connection refused для DNS. После этого код усилен: временный адрес принимается только после Registered tunnel connection и проверки собственного /health. Реальный маршрут в обновлённой версии ещё не подтверждён.
- Реальное открытие Mini App в Telegram и доставка сообщений не проверены без BOT_TOKEN.
- PyCharm-конфигурация подготовлена и XML проверен; нажатие Run в самой программе PyCharm не выполнялось. Проверен тот же main.py через Python, независимо от рабочей папки.

При первом реальном запуске нужны ключ тестового бота и работающий HTTPS (Cloudflare в доступной сети либо собственный домен). Ни ключи, ни базы, ни пользовательские данные не входят в архив.
