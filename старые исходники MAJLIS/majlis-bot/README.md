# MAJLIS — тестовый бот и Telegram Mini App

Рабочая локальная версия по собеседованию и скриншотам. Это самостоятельный новый проект, не исходники существующего @majlis_agency_bot. Действующий бот не изменялся.

## Основной запуск из PyCharm — версия 0.2

Открыть **main.py** и нажать **Run**. Бот, сервер и временный HTTPS запускаются вместе. Настройки Telegram находятся в **telegram.env**, образец — **telegram.env.example**. Пошаговая инструкция: **TELEGRAM_START.md**. Прежний server.py остаётся отдельным локальным демо-просмотром.

В main.py режим Telegram всегда live и использует отдельную базу. Без MANAGER_IDS все аккаунты остаются покупателями; /id позволяет получить свой ID, после чего его можно добавить в настройки и перезапустить. Команды: /start, /status, /id, /manager, /help. При старте проверяется токен и наличие webhook; чужой webhook не удаляется.

## Что реализовано

- Кабинет покупателя: его заказы, номер, товар, сумма, этап и история доставки, предварительная/подтверждённая дата.
- Понятное состояние без заказов, обновление данных, ошибки загрузки.
- Панель менеджера: поиск, создание заказа, привязка Telegram ID, редактирование партии и даты, изменение этапа.
- SQLite: данные сохраняются между перезапусками.
- Очередь уведомлений с повторными попытками; отдельный Telegram-процесс доставляет сообщения.
- Команды /start, /status, /help и кнопка открытия Mini App.
- Live-вход по проверенной подписи Telegram initData и времени выдачи; менеджеры определяются сервером по MANAGER_IDS.
- HTTP-приём подписанных событий партии и защита от повторного event_id.
- Ручная привязка HTTPS-платёжной ссылки только с разрешённого домена.
- Проверяемый CSV-импорт: пробный запуск, атомарный перенос, обнаружение конфликтов и повторного импорта; уведомления при импорте не рассылаются.

## Что пока не подключено

Токен отдельного тестового бота пока не предоставлен. Для публичного HTTPS добавлен автоматический временный туннель в main.py. Поэтому фактический вход из Telegram и реальная отправка сообщений ещё не проверены. Конкретные карго, доставка, сайт, автоматическое создание ссылок и подтверждение оплаты не подключены. Предложенные этапы доставки требуют согласования с магазином. Импорт из фактической старой базы потребует её схемы и выгрузки; generic CSV-импорт не подтверждает совместимость с ней.

## Локальный просмотр

Нужен Python 3.10 или новее. Для Telegram-режима установите зависимость: `python -m pip install -r requirements.txt`. Локальный server.py использует стандартную библиотеку.

Из папки проекта:

```sh
python3 server.py
```

Открыть http://127.0.0.1:8765. В верхней полосе переключаются «Покупатель», «Без заказов», «Менеджер». Заказы, цены, даты, ID и события в этом режиме демонстрационные. Demo не отправляет сообщения и не принимает внешние интеграционные события. Она доступна только на localhost. Не публиковать demo через туннель или прокси: переключатель ролей — средство проверки, не авторизация.

Демонстрационная база: data/demo.sqlite3. Live должна использовать отдельную базу.

## Подключение отдельного тестового Telegram-бота

1. В официальном @BotFather выполнить /newbot и создать отдельного бота. Не использовать токен действующего магазина.
2. Скопировать .env.example в .env и заполнить токен **локально**, не отправлять его в чат, не добавлять в репозиторий.
3. Указать:

```dotenv
APP_MODE=live
HOST=127.0.0.1
PORT=8765
DB_PATH=data/live.sqlite3
BOT_TOKEN=локальный_токен_тестового_бота
MINI_APP_URL=https://ваш-домен
MANAGER_IDS=ваш_telegram_id
CATALOG_URL=
SUPPORT_URL=
PAYMENT_HOSTS=
INTEGRATION_SECRET=
```

MANAGER_IDS — числовые ID менеджеров через запятую. ID можно взять из ранее полученного личного сообщения /start в существующем боте, не отправляя номер посторонним сервисам. Сервер выдаёт роль по проверенному ID, клиент не может назначить её себе.

4. Разместить HTTP-приложение за HTTPS-прокси с доверенным сертификатом. MINI_APP_URL должен вести на это приложение. В main.py временный URL создаётся автоматически при запуске в режиме cloudflare; ручные процессы ниже — альтернативный способ.
5. Запустить два процесса из папки проекта:

```sh
python3 server.py
```

```sh
python3 bot.py
```

Процесс bot.py устанавливает команды и кнопку меню **только для бота, чей токен указан локально**. На один токен запускать один процесс. Если на нём ранее работал webhook, его нужно отдельно отключить перед polling. Скрипт намеренно не удаляет webhook и накопленные обновления автоматически.

6. Открыть тестового бота, выполнить /start и открыть кабинет. Менеджер создаёт тестовый заказ для ID покупателя. Проверить изменение этапа и фактическое получение сообщения.

Кнопка Mini App использует HTTPS URL, сервер проверяет initData согласно [документации Telegram](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app). Команды и отправка сообщений описаны в [Bot API](https://core.telegram.org/bots/api). Возраст входных данных ограничен одним часом, затем кабинет нужно переоткрыть.

## Оплата

Пока реализовано только сохранение существующей ссылки менеджером. Для активации указать точные домены провайдера в PAYMENT_HOSTS, через запятую, без схемы и пути. Поле не создаёт платёж и не подтверждает его. Нужны отдельный адаптер провайдера, привязка суммы/заказа и проверенные события оплаты. В демо реальные платежи не настроены.

## Подписанные события карго

Live endpoint: POST /api/integrations/events, Content-Type: application/json.

```json
{"event_id":"unique-event-001","shipment":"PALLET-001","status":"in_transit"}
```

INTEGRATION_SECRET — минимум 32 случайных символа. Отправитель добавляет X-Event-Timestamp (Unix seconds) и X-Event-Signature — hex HMAC-SHA256 от байтов `timestamp + '.' + raw_json_body`, ключ INTEGRATION_SECRET. Допустимое отклонение времени — 300 секунд. Повтор event_id не создаёт повторные изменения. Все заказы указанной партии получают этап. Это входной контракт, не готовое подключение неизвестной карго-системы.

До эксплуатации нужно согласовать таблицу соответствия внешних статусов, обработку событий вне порядка, задержек, отмен и возвратов. Сейчас менеджеру разрешены ручные изменения этапа, включая исправления.

## Перенос данных

CSV в UTF-8. Обязательные поля:

```text
number,customer_id,customer_name,item,amount,status
```

Дополнительные: shipment, eta (YYYY-MM-DD). amount — положительное целое число в копейках. Внутренние статусы: confirmed, purchased, in_transit, customs, warehouse, last_mile, delivered. Формат необходимо сопоставить с реальными данными старого бота.

Пробный импорт в отдельную live-базу:

```sh
python3 migrate.py export.csv --db data/import-preview.sqlite3
```

После резервного копирования целевой базы и проверки результатов:

```sh
python3 migrate.py export.csv --db data/live.sqlite3 --apply
```

Без --apply новые заказы не сохраняются. Существующие отличающиеся записи останавливают импорт, весь пакет откатывается. Не запускать миграцию активной базы одновременно с рабочими процессами до согласования окна переноса.

## Проверки

```sh
python3 -m unittest discover -s tests -v
```

Проверяются подпись и срок входа, разграничение доступа по HTTP, блокировка demo-подмены в live, создание/изменение заказа, подписанные события и повторная доставка, безопасные домены платёжных ссылок, CSV dry-run/откат и очередь сообщений. Telegram API в тестах очереди заменён контролируемой имитацией — это не проверка реальной доставки.

## Перед использованием магазином

Согласовать статусы и права сотрудников; подключить реальные сервисы; проверить реальные Telegram-сценарии на тестовом боте; настроить HTTPS, резервные копии, наблюдение за ошибками, восстановление и ограничение нагрузки на прокси. Встроенный HTTP-сервер предназначен для небольшой тестовой версии. Нужны производственная инфраструктура и нагрузочная проверка до запуска магазина.

Очередь отправляет сообщения с повторными попытками. После сетевого сбоя, когда Telegram уже принял сообщение, а ответ потерялся, возможен повтор: гарантия ровно одной доставки не заявляется. После постоянной ошибки уведомление отмечается failed; автоматического ручного повторения из панели пока нет.
