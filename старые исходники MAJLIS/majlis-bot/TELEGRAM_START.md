# Запуск MAJLIS из PyCharm и открытие Mini App внутри Telegram

## Как устроен запуск

Вы запускаете **main.py**. Он запускает сервер Mini App, получает HTTPS-адрес через установленный cloudflared, проверяет доступность своего сервера по этому адресу и запускает Telegram-бота. Бот проверяет токен, устанавливает команды и кнопку **«Кабинет»**. Сообщение /start содержит кнопку **«Открыть кабинет»** типа web_app: она открывает приложение внутри Telegram.

Для постоянного HTTPS-домена предусмотрен режим external. Для тестов на вашем компьютере можно оставить cloudflare. Временный адрес меняется при перезапуске, и бот обновляет кнопку меню. Старое сообщение /start может содержать старый адрес: после перезапуска отправьте /start снова или воспользуйтесь новой кнопкой меню «Кабинет».

## Первый запуск — пошагово

1. Распакуйте архив в отдельную папку, например **majlis-bot**.
2. В PyCharm выберите **Open** и откройте эту папку целиком.
3. Выберите интерпретатор **Python 3.10 или новее**. Можно создать обычное виртуальное окружение. В терминале PyCharm выполните **python -m pip install -r requirements.txt**. Это установит truststore для HTTPS с системными сертификатами, без отключения проверки TLS.
4. Создайте **telegram.env**: скопируйте файл **telegram.env.example** и переименуйте копию. На этом компьютере файл уже подготовлен в исходной папке проекта. В архив он намеренно не включён, чтобы не передать будущий токен.
5. В строку BOT_TOKEN вставьте ключ **нового тестового бота**. Делайте это в локальном редакторе. Не присылайте ключ в чат.
6. Оставьте HTTPS_MODE=cloudflare. На вашем Mac установлен cloudflared по пути /opt/homebrew/bin/cloudflared — программа умеет находить его автоматически, даже если PyCharm не получил PATH терминала. На другом компьютере потребуется установить cloudflared с [официальной страницы Cloudflare](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/downloads/) и при необходимости вписать CLOUDFLARED_PATH.
7. Откройте **main.py**, нажмите правой кнопкой в редакторе и выберите **Run 'main'**. Альтернатива: готовая конфигурация **MAJLIS Telegram** из папки .run; если PyCharm просит выбрать модуль/интерпретатор, укажите текущий проект и Python.
8. Дождитесь сообщения **«Бот @… запущен»**. При ошибке программа напишет, что проверить, и остановит связанные процессы. Токен в журнал не выводится.
9. Откройте своего тестового бота в Telegram и отправьте **/start**. Нажмите **«Открыть кабинет»** либо **«Кабинет»** в меню чата.

Минимальный telegram.env:

```dotenv
BOT_TOKEN=вставьте_свой_токен_локально
MANAGER_IDS=
HTTPS_MODE=cloudflare
MINI_APP_URL=
PORT=8875
DB_PATH=data/telegram.sqlite3
CLOUDFLARED_PATH=
CATALOG_URL=
SUPPORT_URL=
PAYMENT_HOSTS=
INTEGRATION_SECRET=
```

В первый раз кабинет будет пустым. Это ожидаемо: Telegram-режим не создаёт вымышленные покупки, суммы или пользователей.

## Как назначить себя менеджером и создать тестовый заказ

1. Отправьте **/id** новому боту. Он покажет ваш числовой Telegram ID.
2. В telegram.env заполните **MANAGER_IDS=ваш_числовой_ID**. Для нескольких менеджеров — числа через запятую.
3. Остановите main.py в PyCharm и запустите снова.
4. Отправьте **/manager** или **/start**, затем откройте кабинет. В нём появится панель менеджера.
5. Создайте тестовый заказ. Если тестируете самостоятельно, укажите свой ID покупателя. Для проверки клиентского вида другим аккаунтом используйте его ID после того, как он сам отправит /start боту.
6. Измените этап доставки. Покупателю будет поставлено в очередь уведомление; процесс бота попытается отправить его в личный чат.

Менеджерский аккаунт видит панель менеджера. Для тестирования обычного покупателя удобнее отдельный Telegram-аккаунт без менеджерских прав. Локальный демо-просмотр позволяет переключать роли, но внутри Telegram такого переключателя нет.

## Команды бота

- /start — приветствие и открытие Mini App.
- /status — текущие этапы ваших заказов.
- /id — ваш Telegram ID.
- /manager — открытие кабинета с проверкой менеджерского доступа.
- /help — помощь.

Mini App проверяет подписанные Telegram-данные на сервере. Пользователь видит только свои заказы, менеджер — заказы магазина. Внешний HTTP-заголовок демонстрационного профиля в Telegram-режиме не даёт доступа.

## Запуск без Telegram

В конфигурации запуска PyCharm добавьте параметр **--demo** или выполните:

```sh
python3 main.py --demo
```

Открыть http://127.0.0.1:8875. Это отдельная база data/preview.sqlite3 с демонстрационными заказами. Туннель и Telegram в этом режиме не запускаются. Прежняя демонстрация на порту 8765 может работать независимо.

## Проверка настроек без запуска

```sh
python3 main.py --check
```

Проверяет обязательные поля, зависимость truststore и наличие cloudflared, но не обращается к Telegram и не подтверждает правильность ключа. Токен проверяется через getMe только при реальном запуске.

## Постоянный адрес и дальнейшие интеграции

Для сервера с постоянным HTTPS-адресом:

```dotenv
HTTPS_MODE=external
MINI_APP_URL=https://ваш-домен
```

Адрес должен вести на текущий экземпляр приложения — главная страница, /health и /api должны проксироваться на него. main.py проверяет идентификатор сервера перед настройкой кнопки бота. Просто заменить URL на сторонний сайт недостаточно.

Тестовый Cloudflare Tunnel работает только пока запущены процессы и компьютер подключён к сети. Это режим разработки, не постоянный хостинг. Для магазина нужно разместить проект на сервере, настроить стабильный домен, наблюдение, резервные копии и согласовать реальные интеграции.

В проекте есть подписанный приём событий партии, generic CSV-импорт и ручная привязка разрешённых платёжных ссылок. Адаптеры неизвестной карго-системы, службы доставки, сайта и автоматическое создание платежей ещё не подключены.

## Если что-то не запускается

| Сообщение/симптом | Что сделать |
|---|---|
| Заполните BOT_TOKEN | Вставить ключ в telegram.env, сохранить файл |
| Telegram отклонил токен | Проверить, скопирован ли весь ключ, не отозван ли он |
| cloudflared не найден | Установить официальный cloudflared; указать полный путь в CLOUDFLARED_PATH |
| Порт занят | Остановить другой запуск или изменить PORT |
| Проект уже запущен | Остановить прежний main.py; блокировка освобождается ОС при завершении |
| Другой процесс получает обновления | Остановить другую копию бота с тем же токеном |
| У бота настроен webhook | Использовать нового тестового бота; чужой webhook программа не удаляет |
| Туннель не получает адрес | Проверить Интернет, VPN, доступность Cloudflare; проверить пользовательскую конфигурацию cloudflared |
| Нет соединения с Telegram | Проверить Интернет/VPN и доверенные сертификаты интерпретатора Python; проверка сертификата не отключается |
| Старые кнопки не работают после перезапуска | Отправить /start ещё раз: временный URL изменился |
| Кабинет открывается с ошибкой авторизации | Открыть его через кнопку именно нового бота, а не обычным браузером; переоткрыть после истечения данных входа |
| Нет панели менеджера | Проверить MANAGER_IDS, затем перезапустить main.py |

На Windows и других системах код не проверялся в живой среде: предусмотрены совместимые пути и блокировка, но подтверждённые запуски относятся к этому Mac.

## Если локальный DNS не разрешает SRV Cloudflare

Предусмотрен параметр `CLOUDFLARE_DOH_EDGE=1`: публичные серверы Cloudflare определяются через HTTPS DNS-запросы, затем передаются cloudflared. Системные DNS/VPN-настройки не меняются; TLS-проверка остаётся включённой. Этот режим использует механизм StaticEdge из исходников cloudflared и требует доступности Cloudflare по сети.
