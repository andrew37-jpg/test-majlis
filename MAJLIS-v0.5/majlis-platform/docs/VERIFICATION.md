# Проверка версии 0.5 — 14–15.10.2026

Состояние проверяется на отдельной копии и выделенной PostgreSQL-базе с отдельными runtime/migration ролями. Рабочая установка пользователя не обновлялась.

- 65 Python-тестов прошли, без предупреждений после перехода тестового Starlette-клиента на httpx2. Существующие проверки доступа/транзакций сохранены; новые проверяют владение историей, перенос туда/обратно, последовательность/конкуренцию событий, минимальные права, заголовки, pre-auth лимиты, bounded историю, бота/CLI/туннель и потерю leader connection.
- 5 Node-тестов прошли: refresh/more/filter/stale ответы, escaping/деньги и чистые представления карточки/передачи.
- На исходной версии переработанные проверки правильного поведения дали 5 failed / 3 passed. Они больше не утверждают проблемное поведение. Имена тестов в итоговом коде отражают правильный результат; baseline лог сохранён в пакете отчёта.
- Браузерный стенд с вымышленными данными: 100 → load more 200 → refresh 200 → load more 300. Карточка открывается; изменение ID очищает имя и снимает подтверждение; в помощи видна кнопка выгрузки. Это проверка копии UI с mock API/SDK, не реального Telegram.
- Реальный локальный Uvicorn с тестовой базой: HTML/JS-модули 200; public ready 403; internal ready с отдельным health token 200; unsigned bootstrap 401; подписанный покупатель 200; oversized POST 413. Заголовки проверены на ответах.
- pg_dump и restore-test: новая БД, 9 таблиц, структура 28 ограничений, хеши данных совпали; 12 нарушений CHECK/UNIQUE/FK отклонены. Dump 0600, в исходники не включён. ACL restore намеренно не переносит: права проверяются отдельно.
- Local/server Compose: config --quiet прошёл. Это не развёртывание серверного профиля. Ruff/format/Bandit и JS-синтаксис проверяются финальным набором команд в пакете отчёта; точечные nosec объяснены в SECURITY-SCANNERS.md.
- 23 runtime-версии сохранены; добавлены SHA-256 из PyPI. pip download --require-hashes прошёл на текущем macOS/Python 3.12; Windows/другие платформы не проверены.

Во время разработки исправлены: локальная ошибка имени sql в миграторе (первый прогон имел 27 setup errors), несовпадение текстовых CHECK после restore (данные совпадали; теперь сравнивается структура и реальное поведение), предупреждение TestClient. Они не скрыты в окончательных результатах.

Не подтверждены: реальные Telegram HTTP/SSH-сбои, iOS/Android/Windows, Caddy HTTPS на собственном сервере, внешние API/оплата, высокая нагрузка/несколько реплик, полные аварийные RPO/RTO, восстановление production ACL, юридические сроки хранения. Обновление владельцев рабочей PostgreSQL-базы подготовлено, но не выполнено без отдельного согласования административной операции.
