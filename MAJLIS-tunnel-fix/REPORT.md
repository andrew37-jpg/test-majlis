# Восстановление MAJLIS после no tunnel — 16 октября 2026

На пользовательском скриншоте — no tunnel. Первая проверка: локальный 127.0.0.1:8876 не принимал соединение; последний публичный адрес из runtime.json возвращал HTTP 502 и no tunnel.

Консоль PyCharm: после восстановления временного HTTPS обработчик бота завершился с TelegramFailure; launcher сообщил «Telegram worker остановился» и завершил приложение. Конкретный код последней ошибки консоль не сохранила, поэтому нельзя подтвердить, была ли именно последняя ошибка сетевой, ограничением Telegram или ошибкой авторизации. Ранее в той же консоли была временная ошибка Telegram 0.

В коде подтверждено: настройка Telegram.configure выполнялась вне цикла повторов; исключение на этом этапе останавливало worker. Добавлена configure_with_retry в majlis/bot.py: повтор только для ошибок 0, 429 и 5xx, увеличивающаяся задержка до 60 секунд для обычных временных сбоев, retry_after для 429, прерывание при остановке. Перед каждой попыткой проверяется живое соединение владельца PostgreSQL advisory lock. Ошибки 400/401/403/409 остаются явными, webhook автоматически не удаляется.

Изменены majlis/bot.py и добавлен tests/test_bot_startup_retry.py. Настройки, права и бизнес-логика заказов не менялись.

Проверка отдельной тестовой PostgreSQL: 111 Python-тестов прошли за 28.88 секунды. Это 104 прежних + 7 новых случаев повторов, постоянных ошибок, остановки и потери лидерства. Ruff без замечаний; форматирование применено.

Текущий проект перезапущен конфигурацией PyCharm MAJLIS 0.7 — Mini App. Итог: локальный и публичный /health HTTP 200, instance совпадает, getMe подтвердил majlis_test_bot, getChatMenuButton совпадает с актуальным runtime URL. Эти проверки не отправляли сообщений клиентам.

Источники результатов в рабочей папке: work/majlis-tunnel-fix/tests.txt и live-check.json. Исходная копия bot.py сохранена в work/majlis-tunnel-fix/before/bot.py.

Уже открытое окно Telegram сохраняет прежний URL. Нужно закрыть его и открыть актуальную кнопку «Кабинет MAJLIS» в нижнем меню бота. Повторное открытие на устройстве не подтверждено: интерфейс управления Telegram возвращал AXError.notImplemented; видимый старый экран не выдаётся за успешную проверку нового окна.

localhost.run остаётся временным сервисом. Исправление не гарантирует постоянную доступность провайдера, не меняет старые кнопки в сообщениях и не заменяет постоянный сервер/домен.
