# MAJLIS 0.7 · Telegram Mini App и PostgreSQL

Продолжение текущего проекта PyCharm, включая исправление QR-ответов localhost.run. Покупательский и рабочий кабинеты разделены; общедоступного переключателя ролей нет. Правила доступа — на backend.

## Запуск в настроенном PyCharm

Проект: majlis_bot_test/majlis-platform. Выберите конфигурацию **MAJLIS 0.7 — Mini App** и Python 3.12 из .venv проекта, нажмите Run. Docker и сеть должны работать. Вторую копию того же polling-бота не запускайте.

main.py запускает PostgreSQL, применяет миграции, поднимает API, временный HTTPS, bot и отдельный notify worker. Открывайте актуальное меню бота: старые сообщения/окна могут содержать прежний HTTPS-адрес. Stop завершает дочерние процессы, PostgreSQL и Docker volume сохраняются. Не используйте docker compose down -v.

Покупатель открывает обычную кнопку кабинета. Менеджер входит **со своего Telegram ID** через `/manager` после явного назначения; команда отсутствует в общем меню. Рабочий адрес `/manager/` не даёт прав сам по себе. Ввод чужого ID вместо Telegram-авторизации не предусмотрен. Без назначения менеджерский API возвращает 403. Реальный ID покупателя не повышается автоматически.

## Новый компьютер / отдельная установка

Нужны Python 3.12, Docker с Compose и OpenSSH. В папке приложения:

```sh
python -m venv .venv
source .venv/bin/activate
python -m pip install --require-hashes -r requirements.lock
```

Windows: используйте .venv\Scripts\python.exe; живой запуск Windows не проверялся. requirements.txt также ссылается на requirements.lock.

Скопируйте .env.example в .env, заполните BOT_TOKEN локально, задайте отдельные случайные пароли admin/migrator/runtime, соответствующие DATABASE_URL и MIGRATION_DATABASE_URL, HEALTH_TOKEN от 32 символов. Не отправляйте секреты в чат и не включайте их в архивы исходников. Для генерации одного значения:

```sh
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

Изменение пароля в .env не меняет пароль существующей PostgreSQL. Обновление существующей установки: [UPGRADE-0.7](docs/UPGRADE-0.7.md), для прежней 0.4 также [UPGRADE-0.5](docs/UPGRADE-0.5.md).

## Возможности и доступ

- Покупатель: свои заказы, товар/комплектация, сумма, разрешённая ссылка оплаты, этапы/история/сроки, подтверждённые данные отслеживания и обращение в магазин.
- Менеджер: назначенные заказы либо явно разрешённый полный доступ, поиск/фильтры, разрешённые правки, лента изменений. Все обращения — только с отдельным can_read_inbox.
- Сообщения этому боту и обращения из Mini App сохраняются в customer_messages. Личные переписки вне бота недоступны. Вложения представлены типом/подписью; файлы не загружаются. Исходящие ответы менеджера не реализованы.
- MANAGER_IDS сохраняет прежний явно назначенный глобальный доступ к заказам. Он сам по себе не даёт чтение всех сообщений. Полный новый рабочий аккаунт назначается оператором по подтверждённому ID, не кнопкой в Mini App.
- Платёжная ссылка не подтверждает оплату. Изменение товара/суммы убирает устаревший URL из кабинета, но не отменяет provider invoice.

[Кабинеты и назначения](docs/CABINETS-AND-ACCESS.md), [источники и отслеживание](docs/WEBSITE-AND-TRACKING.md), [данные пользователя](docs/PRIVACY.md).

## Проверки и ограничения

Тесты запускаются только с отдельными TEST_DATABASE_URL / TEST_MIGRATION_DATABASE_URL на одной БД с суффиксом _test и разными ролями: [TESTING](docs/TESTING.md). Полный набор: **104 Python**, **9 JavaScript**; интерфейс проверен на 360 px с настоящим тестовым API/PostgreSQL и имитацией Telegram SDK. Это не проверка всех устройств Telegram.

Сайта/API/карго/платёжного провайдера и старой базы заказчика нет: реальные adapters, синхронизация создания заказов и оплата не подключены. [Точные материалы для подключения](docs/WEBSITE-AND-TRACKING.md). Старые данные заказчика не переносились, схема их базы не угадывалась. Нормализованная репетиция — отдельная возможность.

localhost.run — временный HTTPS, требует включённого компьютера и может менять адрес. Серверный Compose/Caddy подготовлены, но стабильное размещение и BotFather Main Mini App отдельно требуют настройки и приёмки. [OPERATIONS](docs/OPERATIONS.md). Приёмка уведомлений, iOS/Android/Windows, внешние API и рабочие сценарии полного менеджерского аккаунта требуют реальных материалов/назначения.
