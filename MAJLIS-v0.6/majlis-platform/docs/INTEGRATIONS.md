# Контракт тестового адаптера

POST /api/integrations/events, Content-Type application/json. Поля: event_id (уникальный, до 128), shipment (партия, до 100), status (из текущего словаря), sequence (положительное целое BIGINT). sequence в production обязательна, в тестовом режиме без неё работает только монотонность этапов.

X-Event-Timestamp — Unix seconds, допустимый сдвиг 300 секунд. X-Event-Signature — hex HMAC-SHA256(INTEGRATION_SECRET, timestamp + '.' + точные bytes JSON). Ключ минимум 32 символа, хранится локально. Не отправляйте его в браузер.

Текущая конфигурация имеет один секрет и один логический поток; sequence сравнивается для каждого заказа партии. Адаптер должен обеспечить сравнимую возрастающую sequence для потока партии. Если провайдер её не предоставляет, необходимо определить преобразование порядка/времени с заказчиком: не подключайте случайно разные независимые счётчики под одним секретом.

Старое событие не откатывает доставленный заказ; повтор event_id с той же нагрузкой не создаёт side effects, другая нагрузка под тем же ID — 409. Известная партия с запоздавшим событием получает updated:0. Неизвестная партия — 404 с откатом квитанции, событие можно повторить после привязки. Ручные коррекции менеджера независимы от автоматического монотонного продвижения.

Для отмен/возвратов сначала нужны согласованные состояния и переходы: они не существуют в текущем словаре и не выдумываются адаптером. Отправка платёжных событий не реализована. Нельзя трактовать ручную ссылку как paid.
